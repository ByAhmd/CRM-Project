# Decision register

Every decision that shapes the CRM's architecture, data or business rules. Owner decisions (D-n) were
answered on 2026-09-05 to the questions raised in [OPEN_DECISIONS.md](OPEN_DECISIONS.md). Architect
decisions (A-n) are implementation choices within the established standard, listed for traceability.
New decisions are appended; superseded ones are struck through with a pointer to their replacement.

## Owner decisions

| # | Decision | Consequence in the build |
|---|---|---|
| **D-1** | **Production target = Hostinger shared hosting** (Stockflow's host). | Database queue drained by the scheduler; assets built in CI and shipped; no Supervisor/Node/`exec()` on the server; PHP 8.3 language floor; **the database engine is confirmed in writing before the first production migration** — every CHECK/JSON migration goes through the engine-aware `EnumCheck` helper. |
| **D-2** | **Single organisation.** No tenant column. | Organisation settings are a `settings` singleton; visibility is owner/team only; spatie `teams` feature off; no global tenant scope. Retrofitting tenancy later is a documented one-way door. |
| **D-3** | **spatie tables are the runtime permission authority.** | Typed keys in `App\Enums\Permission`; defaults in `App\Support\Access\RolePermissionMatrix` seeded by `RolesAndPermissionsSeeder`; drift test pins the seeded defaults; own bilingual **Roles** resource for super admins; every role/permission change audited; Filament Shield **not** installed. |
| **D-4** | **Permission-driven visibility with teams.** Defaults: `sales_rep` = own, `sales_manager` = team, `admin`/`support`/`read_only` = all. **Sales reps may not reassign their own records**; only holders of `{entity}.assign` may reassign. | `{entity}.view_team` / `{entity}.view_all` permissions; `teams` table, one team per user (`users.team_id`), optional team manager; `RecordVisibilityResolver` on every query path; reassignment audited and notified. |
| **D-5** | **Arabic is the default locale, English the fallback.** | `app.locale = ar`, `app.fallback_locale = en`; RTL first; per-user locale persisted; Filament Arabic gaps patched under `lang/vendor`. |
| **D-6** | **One `accounts` entity with a lifecycle `type`** (prospect / customer / partner / other). A prospect becomes a customer automatically on its first won deal; admins may set the type manually. **A contact belongs to exactly one account.** | `accounts.type`, `accounts.customer_since`; `DealCloseService` promotes the account; `contacts.account_id` single nullable FK, no account pivot. |
| **D-7** | **Lead lifecycle.** Default statuses New → Contacted → Qualified → Converted, plus Unqualified (terminal, reopenable). **A qualification note is required** when moving into a status of kind *qualified*. **Rule-based scoring** with optional manual override. **Leads may only be converted from a Qualified status.** | `lead_statuses` seeded with these kinds; `LeadStatusWorkflow` enforces the note on qualification; `lead_scoring_rules` table + `LeadScoringService` (points per source, status, activity recency, filled fields) + `leads.score` and `leads.score_override`; `LeadConversionWorkflow` refuses non-qualified leads. |
| **D-8** | **Product catalogue + deal line items**, single currency. Currency defaults to **SAR**, timezone to **Asia/Riyadh**, both editable in General Settings. Forecast categories (pipeline / best case / commit / omitted) and stage probabilities with per-deal override are included. | `products`, `deal_products`; deal amount computed from lines (manual amount allowed when there are no lines); `deals.forecast_category`, `deals.probability` override; `settings` keys `general.currency`, `general.timezone`. Line-item recalculation writes the amount through a normal `save()` so the change is audited as `deal.updated`. |
| **D-9** | **Typed custom-field engine in v1 for Leads, Contacts, Accounts and Deals.** | `custom_fields` + `custom_field_values` (typed columns); runtime form/table/filter components; import/export columns; no JSON bags. |
| **D-10** | **Templated email sending through the application mailer**, logged automatically as email activities. No mailbox synchronisation in v1. **Log mail driver during development** until production SMTP is configured. | `email_templates` table (bilingual, merge tags); `EmailSendService` writes an outbound `email` activity; mail notifications gated on a real transport; `MAIL_MAILER=log` locally; preflight warns when production mail is `log`. |
| **D-11** | **MFA available to all users, optional.** Password policy: minimum 12 characters, mixed case, a number, uncompromised. Session lifetime 120 minutes, secure cookies in production. **Self-registration disabled; users are invite-only.** | Filament app + email MFA providers with `isRequired: false`; `Password::defaults()`; `SESSION_LIFETIME=120`; preflight fails without `SESSION_SECURE_COOKIE=true` in production; no registration page; invitation flow. |
| **D-12** | **Kanban board and calendar built as custom Filament pages** (no packages). | `DealBoard` page on Filament's bundled SortableJS; `Calendar` page on FullCalendar from npm; direction and labels passed from the server; both tested with `Livewire::test`. |
| **D-13** | **Retention and export policy.** Audit ledger 730 days (configurable), pruned weekly; timeline entries permanent; soft-deleted records kept indefinitely with admin restoration. **Sales reps may export only records inside their visibility scope; managers and above export everything they may view.** | `config('crm.audit.retention_days') = 730` + weekly `activitylog:clean`; no force-delete UI; `{entity}.export` granted to every role incl. `sales_rep`, exporters always pass through `RecordVisibilityResolver`. |

## Architect decisions

| # | Decision |
|---|---|
| A-1 | Stack pinned to the Stockflow line: Laravel `^13.0`, Filament `^5.0`, PHP `^8.3` (Herd 8.4 locally, 8.3 in CI), MySQL 8.4, spatie/laravel-permission `^8`, spatie/laravel-activitylog `^4.12` (5.x needs PHP 8.4), bezhansalleh/filament-language-switch `^5`, PHPUnit `^12` (13.x needs PHP 8.4), Larastan `^3`, Pint `^1`, Vite 8, Tailwind 4. |
| A-2 | One Filament panel at `/admin`; no multi-panel layer, launcher or platform tier. Resources and pages discovered, with a structural test that every resource maps to a policy and permission keys. |
| A-3 | Resource composition and naming as Stockflow (`Resource` + `Schemas/`, `Tables/`, `Pages/`, `RelationManagers/`), `final` + `declare(strict_types=1)` everywhere, attribute-based model configuration, `casts()` method, `@property` docblocks for every cast. |
| A-4 | Configurable business data lives in bilingual lookup rows with a behavioural `kind` enum; code enums only where code must reason; `EnumCheck` DB constraints on code-enum columns. |
| A-5 | spatie/laravel-activitylog is the audit ledger (append-only observer, own `audit.view` permission, indexes on subject/causer); `deal_stage_logs` and `lead_status_logs` hold stage/status history; `TimelineReader` composes the per-record timeline. |
| A-6 | Own `attachments` table on the private `local` disk, server-side MIME allowlist, UUID file names, authorised download route; no media-library package. |
| A-7 | Filament built-in Import/Export actions with importers/exporters, private disk, read-only Imports/Exports resources under System, `model:prune` weekly. Amended (2026-09-15, as built): `model:prune` runs daily (`routes/console.php`). |
| A-8 | Filament global search with searchable attributes and scoped queries; own `saved_views` table; table filters/sort/search persisted in session. Amended (owner, 2026-09-17): **saved views are withdrawn.** The owner reviewed the three list-page buttons («العروض» / «حفظ العرض» / «مسح العرض») and found them of no use, so the feature was removed whole — actions, `HasSavedViews`, `SavedViewActions`, `SavedView`, `SavedViewPolicy`, `SavedViewService`, `TableState`, the `saved_view.share` permission, the `saved_views` lang files, the demo rows and the table (`2026_09_17_100001_drop_saved_views_table`, reversible). Global search and the session-persisted filters/sort/search of A-8 are untouched: a list still reopens the way the user left it, which is what the buttons duplicated. |
| A-9 | One Tailwind 4 theme file with CRM tokens (`--crm-*`), `.dark` redefinitions, generated colour ramp; light/dark/system via Filament's theme switcher. |
| A-10 | Notes are mutable with edit history in the ledger; activities are immutable events; tasks are mutable with daily/weekly/monthly recurrence and idempotent reminders. |
| A-11 | Duplicate detection = exact match on normalised email/phone (warn on create and import, never block) plus a merge action; no fuzzy matching in v1. Amended (quality pass, 2026-09-14): the live form warning and the conversion-modal contact suggestion are limited to the actor's visible scope; a match outside it is acknowledged only with a generic sentence carrying no identifying data (`merge.warnings.outside_reach`), so the warning is never an enumeration oracle. The merge service and other trusted server-side callers keep the organisation-wide lookup. |
| A-12 | Six roles seeded: `super_admin`, `admin`, `sales_manager`, `sales_rep`, `support`, `read_only`. `super_admin` holds every permission through an explicit full grant in `RolePermissionMatrix`, re-granted by `RolesAndPermissionsSeeder` on every seed (no `Gate::before`); the role is locked (never renamed, edited, deleted or stripped). Only a `roles.manage` holder grants, removes or edits `super_admin`; the last active super admin cannot be demoted, disabled, set to pending or deleted; nobody may disable their own account. |
| A-13 | Tests: PHPUnit 12 on MySQL `crm_testing`; PHPStan level 5 with `checkModelProperties`, no baseline; Pint default preset; `composer check` = lint + analyse + test, also in CI. |
| A-14 | Documentation and git conventions mirror Stockflow: README, CLAUDE.md, CONTRIBUTING.md, `docs/`, conventional commits, `master` (production) / `develop` (integration). |
| A-15 | Out of scope for v1 unless decided later: mailbox sync, WhatsApp/SMS, telephony, AI features, public web-to-lead forms, quotes/invoices, multi-currency, API/Sanctum. |
| A-16 | Module language files gain a fixed `options` sub-key for translated option lists that are neither enum labels nor field labels (first use: `activity_types.options.icons.*`, the curated Heroicon names offered in the icon select). The sub-key vocabulary in CLAUDE.md section 3 is extended accordingly. |
| A-17 | Record timelines are read models composed at request time (`TimelineReader`), embedded lazily on the view pages; a task created from a calendar day cell is due at 09:00 organisation time (`CalendarFeed::DEFAULT_DUE_HOUR`); FullCalendar (MIT) is the only front-end dependency added for D-12. |
| A-18 | ~~Saved views (A-8) are strictly personal preferences: a shared view is offered to colleagues but a default view only ever applies to its owner; stale view state (renamed constraints, columns, sorts) is sanitised before it is applied.~~ Withdrawn (owner, 2026-09-17) with the saved-views feature itself — see the A-8 amendment: the buttons were unused, so the rule they governed no longer has a subject. Imports create, update and reassign records only through the entity's own policy verbs (`create`, `update`, `{entity}.assign`) on top of `{entity}.import`; exports and importer duplicate detection see only the importer's visible scope (D-13). Import and export history rows are pruned after 90 days with their files. Amended (2026-09-15, as built): import runs are kept 90 days (`Import::RETENTION_DAYS`), export runs and their files 30 days (`Export::RETENTION_DAYS`). |
| A-19 | Dashboard and report filter bars are live (no apply step) and lay their fields out in responsive columns rather than the single column CLAUDE.md prescribes for record forms: a filter bar is a toolbar, and an unused `apply` label would be a dead translation key. Every figure on a dashboard widget or report page is computed from a `RecordVisibilityResolver`-scoped query; the owner, team and pipeline filters only narrow it. Time buckets (months, days) are folded in PHP in the organisation timezone, never with SQL date functions, because the shared host has no MySQL timezone tables and the organisation timezone is a runtime setting. |
| A-20 | Quality pass (2026-09-14). Soft-deleted records are frozen: every write verb refuses a trashed record and restore is the only action left. A change of owner through any form, assign action or importer goes through `RecordAssignmentService`; only active users are assignable. Amended (2026-09-15, as built): an import row that names a new owner for an existing record (update duplicate strategy) needs the record's `assign` policy verb and is handed to `RecordAssignmentService` inside the row's savepoint (`ResolvesImportLookups::fillOwner()` / `reassignPendingOwner()`), so it writes the `{entity}.assigned` audit event with the importer as causer and notifies the new owner; a refused target fails the row and rolls it back. A new record created for another owner is a creation, not a reassignment, on the create pages and in imports alike (`tests/Feature/ImportExport/ImportReassignmentTest.php`). The account lifecycle type is set by hand only with `account.set_type` (admins), otherwise a prospect becomes a customer on its first won deal (D-6); `activity.assign` gates the activity owner field. Import/export history: a user always sees and downloads their own runs; `exports.view` / `imports.view` open another user's run only for entities the holder reaches at all level, on the history screens and on Filament's download routes alike. Notes written on a contact or deal appear on the account page and its timeline only when the viewer may read that contact or deal (`ReadableNoteScope`). Event notifications reach only recipients who can open the record, never disabled or pending accounts. Every Filament date-time column, entry and picker renders and reads in the organisation timezone (`FilamentTimezone` from General Settings); values stay stored in `app.timezone`; report and dashboard buckets fold in PHP. Laravel's mail and notification views are published under `resources/views/vendor/{mail,notifications}`; their strings come from `lang/*/email.php`; mail direction follows the rendering locale and the salutation comes from the published view. Lazy loading is prevented for the whole test suite (`tests/TestCase.php`), so any N+1 fails the test that exercises it. Lead scores are recomputed daily at 03:00 (`RescoreLeads`, batched by id) so activity-recency points expire. Friendly translated error pages (403, 404, 419, 429, 500, 503) share one template with no build, session or database dependency. |
| A-21 | Quality pass, engine and search closure (2026-09-15). **Migrations are proven on MySQL 8.4 and MariaDB 10.4** (8.4.11 and 10.4.32): `migrate:fresh --seed`, `migrate:rollback --step=500`, `migrate`, `db:seed` twice and `app:preflight` exit 0 on both, and the full suite shows no engine-difference failure. The few statements the engines spell differently branch on `App\Support\Database\DatabaseEngine::isMariaDb()` (Laravel's own `MySqlConnection::isMaria()`, so both the `mysql` and `mariadb` drivers work), used by `EnumCheck` and migration `2026_09_14_400011`. Differences recorded: (1) MariaDB rejects `NULL` / `NOT NULL` on a generated column, so `lead_scoring_rules.reference_key`, `field_key` and `within_days_key` are declared NOT NULL on MySQL only and read nullable in `information_schema` on MariaDB — `COALESCE` still stores no NULL, so the unique key refuses the same duplicates; (2) RESTRICT foreign keys on STORED generated columns are accepted and enforced on both (MariaDB's `SHOW CREATE TABLE` omits the default `ON DELETE RESTRICT`); (3) dropping a CHECK is `DROP CONSTRAINT IF EXISTS` on MariaDB and `DROP CHECK` on MySQL (`EnumCheck`); (4) MariaDB 10.4 has `explicit_defaults_for_timestamp` off, so `lead_status_logs.changed_at` and `deal_stage_logs.changed_at` carry an implicit `ON UPDATE current_timestamp()` between their create migrations and `400008` / `400009` (and again if those are rolled back) — none remains after a full migrate; (5) `json` is `LONGTEXT` with a `json_valid()` CHECK on MariaDB; (6) `artisan db:show` fails on MariaDB 10.4 (framework command, no app impact). The DATETIME conversions `400006` … `400010` refuse to roll back while a value lies outside the TIMESTAMP range, naming table, column and rows (`App\Support\Database\TimestampRange`, `tests/Feature/Database/TimestampRollbackGuardTest.php`). Only 10.4 was tested: the production engine and version are still confirmed in writing before the first production migration (D-1). **Global search is limited to the five resources of A-8** named in plan section 3.8 (Lead, Contact, Account, Deal, Task); every other resource sets `$isGloballySearchable = false`. |
| A-22 | Responsive form and view sections (owner's UI/UX round, 2026-09-20). The owner asked for a friendlier, more responsive panel; forms and view pages laid every section out as one full-width column on every screen (`->columns(1)` on every Section, the pre-A-22 convention). **Every Section now declares its column map explicitly**: `->columns(['default' => 1, 'lg' => 2])` where the section holds short fields that pair (names, email/phone, source/priority, owner/tags, dates, lookup names, toggles), `->columns(1)` deliberately where the content is a single field, a long textarea, a repeater or an infolist grid that already manages its own density — never an implicit default. Inside a 2-column section, a full-width component says `->columnSpanFull()`: textareas, duplicate warnings, headline fields (account name, deal title, task title), the type discriminators of the custom-field form, and the injected custom-fields section (`CustomFieldsSchema`), whose own internals also pair `['default' => 1, 'lg' => 2]` with textarea fields spanning the row. The `Grid::make(2)` wrappers that used to pair fields inside single-column sections were flattened into the section's own map (same breakpoints: an int means `lg`), so nothing moved semantically and source order — the mobile order — is unchanged; RTL and LTR need no compensation because CSS grid follows the document direction. **The mobile guarantee: `'default' => 1` keeps every phone single-column**, and the top-level Schema of every form and infolist stays `->columns(1)` so sections stack. The convention is pinned by `tests/Feature/QualityPass/Usability/SchemaColumnsTest.php`, which walks every resource form and infolist (plus the pipeline stage form) and fails any Section without an explicit int or `default`-keyed declaration. |
