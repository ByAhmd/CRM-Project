# Decision register

Every decision that shapes the CRM's architecture, data or business rules. Owner decisions (D-n) were
answered on 2026-09-05 to the questions raised in [OPEN_DECISIONS.md](OPEN_DECISIONS.md). Architect
decisions (A-n) are implementation choices within the established standard, listed for traceability.
New decisions are appended; superseded ones are struck through with a pointer to their replacement.

The tip rule was added after an adversarial review of the trigger (two skeptics confirmed from GitHub's documentation that a re-run of a CI run fires a new `completed` event): without it, re-running an older commit's CI would deploy that commit over a newer release whose migrations had already run. Releases never overlap: `concurrency: deploy` without cancellation sits on the deploy job, not the workflow, because every CI completion creates a Deploy run and a skipped one must not replace a waiting green deploy under GitHub's one-pending-run rule.
